# Звіт з Лабораторної роботи №1

## Код компонента App.jsx

```javascript
import React from 'react';
import './App.css';
import Header from './components/Header';
import Card from './components/molecules/Card/Card';
import Input from './components/atoms/Input/Input';
import Button from './components/atoms/Button/Button';

function App() {
  return (
    <div className="app-container">
      <Header />
      <main className="main-content">
        <Card>
          <h2 className="form-title">
            Ласкаво просимо
          </h2>
          <Input type="email" label="Email" placeholder="Введіть ваш email" />
          <Input type="password" label="Пароль" placeholder="Введіть пароль" />
          
          <div className="button-group">
            <Button variant="primary" onClick={() => console.log('Login clicked')}>
              Увійти
            </Button>
            <Button variant="secondary" onClick={() => console.log('Register clicked')}>
              Реєстрація
            </Button>
          </div>
        </Card>
      </main>
    </div>
  );
}

export default App;
```

## Відповіді на контрольні запитання

### Що таке Atomic Design і навіщо ми розділяємо компоненти на атоми та молекули
**Atomic Design (Атомарний дизайн)** — це методологія створення дизайн-систем, заснована на хімічній аналогії. Вона допомагає розбити складні інтерфейси на базові і послідовні складові.
Розділення компонентів на атоми (найпростіші елементи: кнопки, інпути, іконки) та молекули (комбінація атомів, які працюють разом: форми пошуку, картки з даними) потрібно для:
1. Максимального перевикористання коду.
2. Легкості тестування (простіше протестувати маленьку ізольованую кнопку).
3. Масштабованості та збереження єдиного стилю по всьому проєкту.
4. Спрощення процесу розробки: команда збирає сторінки (організми) з уже готових, надійних і передбачуваних блоків.

### Як працюють CSS Modules і як вони вирішують проблему глобальних імен класів
**CSS Modules** — це підхід, за якого всі імена класів та анімацій генеруються локально за замовчуванням (обробляються збірником, наприклад, Vite або Webpack). 
Проблема звичайного CSS полягає в тому, що всі класи стають глобальними. Якщо в двох компонентах є клас `.button`, стилі можуть перезаписати один одного. CSS Modules вирішують це так:
Ви імпортуєте стилі як об'єкт (`import styles from './Button.module.css'`), і використовуєте `styles.button`. Під час збірки інструмент автоматично створює унікальний клас, наприклад `Button_button__3z2fg`. Завдяки цьому гарантується, що стилі компонента не "витечуть", і глобальні конфлікти імен класів просто неможливі.

### Що таке props.children і в якому компоненті цієї лабораторної роботи ми його використали
`props.children` — це спеціальна властивість (проп) у React, яка використовується для передачі елементів безпосередньо в тіло іншого компонента (вмісту між відкриваючим і закриваючим тегами компонента). Це дозволяє створювати гнучкі компоненти-контейнери, які не знають про свій майбутній вміст заздалегідь.
У цій лабораторній роботі ми використали `children` у таких компонентах:
1. **`Button`** — щоб передавати текст всередину кнопки (`<Button>Увійти</Button>`).
2. **`Card`** — він виступає в ролі молекули-обгортки. Ми передаємо в нього заголовок, інпути та кнопки форми входу.

### Чому атрибут HTML class у JSX записується як className
У JSX (JavaScript XML) ми пишемо не зовсім HTML, ми пишемо JavaScript з синтаксисом, схожим на HTML. Під капотом кожний JSX-тег перетворюється на виклик `React.createElement(...)`.
Слово `class` є зарезервованим ключовим словом у мові JavaScript (воно використовується для створення ES6-класів `class MyClass {...}`). Щоб уникнути конфлікту та помилок при компіляції чи розборі коду в браузері, творці React обрали властивість DOM API `className` (саме так атрибут `class` називається в стандартному JavaScript DOM) для позначення класів у JSX.
