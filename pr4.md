# Практична робота №4: Робота з формами

## Відповіді на контрольні запитання

### 1. Головна різниця полягає в тому, що керовані компоненти зберігають свій стан у React (через useState), тоді як некеровані покладаються на внутрішній стан самого DOM.
У керованих компонентах (Controlled Components) "єдиним джерелом істини" є стан React-компонента. При кожному введенні користувача генерується подія `onChange`, яка оновлює стан (`setState`), а поточне значення стану передається назад в інпут через проп `value`. Це дає розробнику повний контроль над даними в реальному часі (наприклад, для миттєвої валідації чи фільтрації вводу).
У некерованих компонентах (Uncontrolled Components) дані форми обробляються безпосередньо DOM, як у традиційному HTML. Ми витягуємо значення з них зазвичай тільки в момент відправки форми (через `ref`), що потребує менше коду, але унеможливлює миттєву валідацію під час набору тексту.

### 2. Хук useRef використовується для доступу до DOM-елементів (наприклад, для встановлення фокусу) або для некерованих компонентів, коли нам не потрібно викликати перерендер при кожній зміні вводу.
`useRef` відрізняється від `useState` тим, що збереження нових даних у `ref.current` **не викликає** повторного рендерингу компонента. Це робить його ідеальним для зберігання:
- Прямих посилань на реальні DOM-вузли (наприклад, `inputRef.current.focus()` для встановлення курсора).
- Значень у некерованих формах (коли ми просто читаємо значення інпуту перед сабмітом).
- Будь-яких інших мутабельних даних, які мають зберігатися між рендерами, але зміна яких не повинна відображатися на екрані.

### 3. Виклик event.preventDefault() критично важливий, оскільки він блокує стандартну поведінку HTML-форми, яка полягає у відправці запиту на сервер і повному перезавантаженні сторінки, що руйнує стан Single Page Application.
У React-додатках (Single Page Applications) ми прагнемо, щоб сторінка ніколи цілком не перезавантажувалась у браузері, а замість цього динамічно підмінявся лише необхідний контент. Стандартна поведінка браузера при натисканні кнопки `type="submit"` у `<form>` — відправити HTTP-запит (зазвичай GET або POST) і змусити сторінку оновитись. Виклик `e.preventDefault()` скасовує цю поведінку, дозволяючи нам самостійно "перехопити" дані за допомогою JavaScript, провалідувати їх, оновити локальний стан (стейт) React або ж виконати асинхронний запит до API (`fetch`/`axios`) безшовним для користувача способом.
