# Лабораторна робота №4: Маршрутизація

## Структура маршрутів

Наш React-додаток використовує систему маршрутизації на основі компонента `BrowserRouter` з бібліотеки `react-router-dom`. Всі сторінки обгорнуті у спільний макет `MainLayout`, до якого вони підключаються через механізм `Outlet`.

- `/` (головна сторінка, `index`) — рендерить компонент `Home` з інформацією про попередні лабораторні роботи.
- `/feed` — стрічка новин.
- `/feed/:postId` — сторінка окремого поста, яка використовує динамічний сегмент URL для отримання ідентифікатора.
- `/profile` — сторінка особистого кабінету (батьківський маршрут для вкладених сторінок).
  - `/profile` (`index`) — компонент `ProfileOverview` із загальною інформацією.
  - `/profile/settings` — компонент `ProfileSettings` для налаштувань профілю.
- `*` — catch-all маршрут, який активується для будь-якої невідомої адреси та показує 404 сторінку (`NotFound`).

## Фрагменти коду

### Конфігурація Routes (`App.jsx`)
```javascript
<Routes>
  <Route path="/" element={<MainLayout />}>
    <Route index element={<Home />} />
    <Route path="feed" element={<Feed />} />
    <Route path="feed/:postId" element={<PostPage />} />
    <Route path="profile" element={<Profile />}>
      <Route index element={<ProfileOverview />} />
      <Route path="settings" element={<ProfileSettings />} />
    </Route>
    <Route path="*" element={<NotFound />} />
  </Route>
</Routes>
```

### Реалізація Macout з Outlet (`MainLayout.jsx`)
```javascript
<div className={styles.layoutContainer}>
  <header className={styles.header}>
    <nav className={styles.nav}>
      <NavLink to="/" end>Головна</NavLink>
      <NavLink to="/feed">Стрічка новин</NavLink>
      <NavLink to="/profile">Профіль</NavLink>
    </nav>
  </header>
  
  <main className={styles.mainContent}>
    {/* Тут будуть з'являтися дочірні компоненти */}
    <Outlet />
  </main>
</div>
```

## Відповіді на контрольні запитання

### 1. Яка різниця між клієнтською та серверною маршрутизацією?
**Клієнтська маршрутизація** (яка використовується в React за допомогою `react-router-dom`) перехоплює зміну URL у браузері та маніпулює DOM-деревом локально (через JavaScript) без запиту всього HTML-документа із сервера. Це робить переходи між сторінками миттєвими. Натомість **серверна маршрутизація** при кожному переході за посиланням запитує нову HTML-сторінку від сервера, що вимагає часу на завантаження та призводить до повного "мерехтіння" і перезавантаження сторінки у браузері.

### 2. Для чого потрібен атрибут index у Route?
Атрибут `index` вказує, що даний дочірній маршрут є типовим (за замовчуванням) для відповідного батьківського маршруту і повинен відображатися у його `Outlet`, коли URL точно збігається зі шляхом батька (без додаткових сегментів). Наприклад, `<Route index element={<Home />} />` всередині батьківського `/` означає, що перехід просто на `/` покаже компонент `Home`.

### 3. У чому полягає різниця між хуком useNavigate та компонентом Link?
Компонент `<Link>` використовується в JSX для створення "декларативних" клікабельних посилань в інтерфейсі (аналог тегу `<a>`, але для клієнтського рендерингу). Натомість хук `useNavigate` повертає функцію, яку зручно викликати **імперативно** всередині логіки JavaScript коду — наприклад, після успішного збереження форми, після HTTP запиту чи за таймером. Це забезпечує гнучкість управління потоком програми.

### 4. Як реалізовується динамічне підсвічування активних посилань (NavLink)?
У бібліотеці React Router DOM є спеціальний компонент `<NavLink>`, який є розширенням звичайного `<Link>`. Йому можна передати функцію як значення пропу `className` (чи `style`). Ця функція приймає об'єкт з властивістю `isActive` (булеве значення), яка стає `true`, якщо поточний URL збігається з атрибутом `to`. Таким чином можна умовно підставити CSS-клас або стиль "активного" посилання на льоту: `className={({ isActive }) => isActive ? 'my-active-class' : ''}`.

### 5. Для чого потрібен маршрут зі шляхом * (зірочка)?
Маршрут `path="*"` (catch-all маршрут) ловить будь-які сегменти URL, які не збіглися з іншими, чітко прописаними раніше маршрутами. Його типово використовують для обробки помилок 404 (Сторінку не знайдено) і завжди розміщують **останнім** у списку `<Routes>`, щоб він спрацьовував лише тоді, коли жоден із "правильних" шляхів не підійшов.
