# Практична робота №3: Умовний рендеринг

## Відповіді на контрольні запитання

### 1. Чому використання if/else безпосередньо всередині JSX-розмітки призведе до помилки?
JSX — це не справжня мова розмітки на кшталт HTML, а синтаксичний цукор над викликами функцій JavaScript `React.createElement(...)`. JSX-розмітка всередині `return` транслюється у звичайні вирази (expressions) мови JavaScript. У JavaScript не можна писати інструкції (statements) на кшталт `if/else`, `for`, `while` всередині інших виразів або аргументів функцій. Саме тому для умовного рендерингу ми повинні використовувати вирази, які повертають значення: тернарний оператор (`? :`) або логічне "І" (`&&`).

### 2. Яка небезпека криється у використанні числа 0 у лівій частині оператора && в JSX?
Оператор `&&` (логічне "І") повертає перше хибне (falsy) значення, яке зустрінеться, інакше повертає останнє значення. В JavaScript число `0` вважається хибним (falsy), тому вираз `0 && <Component />` поверне `0`. Оскільки React рендерить числа та рядки, то `0` буде безпосередньо виведено на екран користувачеві, замість того, щоб просто приховати елемент. Щоб уникнути цього, ліва частина у `&&` має бути строго булевим (boolean) значенням (наприклад, `count > 0 && <Component />` або `!!count && <Component />`).

### 3. Як реалізувати умовний рендеринг при складній логіці (5+ варіантів)?
Коли є багато умов, вкладені тернарні оператори стають нечитабельними. Найкращі підходи для складної логіки:
- Винести логіку в окрему допоміжну функцію або поза JSX-вираз (`renderContent()`) і використати конструкцію `switch ... case`.
- Використовувати об'єкт-словник (Map-об'єкт) компонентів, що є найбільш елегантним React-патерном: 
  `const componentsMap = { list: <StudentList />, stats: <StatisticsData /> };`
  і далі в JSX викликати `{componentsMap[activeTab]}`.

### 4. В яких випадках використання тернарного оператора є кращим за &&?
Тернарний оператор ідеально підходить, коли потрібно реалізувати вибір *між двома взаємовиключними блоками UI* (або одне, або інше) — як-от кнопка "Увійти" або "Вийти", стан "Завантаження..." або "Дані". 
Натомість логічне "І" (`&&`) слід застосовувати, коли умова ставить вибір "або показати елемент, або не показувати нічого" (наприклад, спливаюче сповіщення чи довідкова панель).

### 5. Як React розуміє, що потрібно перерендерити частину інтерфейсу при зміні вкладки?
Коли ми викликаємо функцію-сеттер (наприклад, `setActiveTab('stats')`), яку повертає хук `useState`, ми сигналізуємо React, що локальний стан цього компонента змінився. Реагуючи на це, React планує повторний реквест на відмальовку (re-render) усього батьківського компонента (`App`). Далі запускається процес Reconciliation: React будує нове віртуальне дерево (Virtual DOM) і порівнює його з поточним. Він бачить, що компонента `<StudentList />` більше немає, а з'явився `<StatisticsData />`, і здійснює мінімально необхідні мутації реального серверного (або браузерного) DOM, щоб узгодити інтерфейс зі змінами.
