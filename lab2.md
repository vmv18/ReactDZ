# Звіт з Лабораторної роботи №2

## Фрагмент коду з використання методу .map() в App.jsx

```javascript
<div className="posts-container">
  <h2 className="feed-title">Стрічка новин</h2>
  {postsData.map((post) => (
    <Post key={post.id} post={post} />
  ))}
</div>
```

## Що відбудеться, якщо видалити атрибут `key`?

Якщо видалити атрибут `key={post.id}` при рендерингу масиву, це серйозно порушить роботу алгоритму **Reconciliation (узгодження)** у React. 

**Reconciliation** — це процес, за допомогою якого React порівнює старе віртуальне дерево DOM (Virtual DOM) з новим, щоб визначити, які реальні зміни потрібно внести в браузерний DOM. При роботі зі списками React використовує `key` для ідентифікації кожного конкретного елемента між рендерами. 

Якщо `key` відсутній або використовується нестабільне значення (як-от індекс масиву при зміні порядку елементів), React:
- Не зможе зрозуміти, які саме елементи додалися, змінилися чи видалилися.
- Буде змушений повністю перемальовувати весь масив або неправильно переробить існуючі вузли. Це значно вдарить по продуктивності програми.
- Може некоректно прив'язати локальний стан (state) до неправильних компонентів (наприклад, стан "відкритого коментаря" перестрибне на інший пост при видаленні першого).
- Виведе попередження (warning) у консолі розробника: *"Warning: Each child in a list should have a unique 'key' prop"*.

## Відповіді на контрольні запитання

### 1. Навіщо потрібен проп `key` у списках React?
Проп `key` використовується для ідентифікації елементів при Reconciliation. Завдяки йому React точно відстежує, які елементи зі списку змінились, були додані або видалені, що дозволяє уникнути зайвого повного перемалювання списку та оновлювати лише потрібну частину DOM.

### 2. Чому не рекомендується використовувати індекс масиву (index) як ключ?
Використання індексу (`0, 1, 2...`) призводить до помилок при зміні порядку елементів, їх додаванні на початок чи видаленні з середини. Коли масив змінюється, індекси зсуваються і React може помилково прив'язати стан одного компонента до іншого компонента (наприклад, введений текст в інпуті "відправиться" до сусіднього елемента), а також помилково перерендерити елементи.

### 3. У чому різниця між імперативним створенням списку (цикл for) та декларативним (map)?
Імперативний підхід (як цикл `for`) описує, *як саме* (крок за кроком) потрібно змінити програму, щоб отримати результат (створити порожній масив, пройтись в циклі, додати елементи). Декларативний підхід (`.map()`) описує, *що* ми хочемо отримати. У React ми просто кажемо: "Ось масив даних, перетвори кожен його елемент на JSX-компонент". Це робить код значно чистішим, надійнішим і відповідає філософії функціонального програмування React.

### 4. Як передати всі властивості об'єкта в компонент одним рядком?
За допомогою Spread attributes (оператора розширення): `{...item}`. Наприклад, якщо у нас є об'єкт `item = { id: 1, title: 'Текст' }`, то запис `<MyComponent {...item} />` буде еквівалентним до `<MyComponent id={item.id} title={item.title} />`.
